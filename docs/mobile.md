# Reading on a phone

The reader is a mobile-first, installable web app. This page covers the two
things that are not obvious: **getting a phone to reach the server**, and
**what the phone platform will and will not let the app do**.

---

## The constraint that shapes everything

Speech is generated by a model on your computer. The phone is a client. So the
phone must be able to reach your machine, and — for the app to be
*installable* — it must reach it over **https**.

Browsers only allow service workers and "Add to Home Screen" in a
[secure context](https://developer.mozilla.org/docs/Web/Security/Secure_Contexts):
`https://`, or `localhost`. A phone opening `http://192.168.1.50:8765` is
neither. Reading still works there — but there is no install, no icon, no
offline shell.

The app says so on screen rather than failing silently.

## Three ways to get https

### 1. A local certificate authority (no accounts, works offline)

```bash
./scripts-tools/make-cert.sh          # detects your LAN addresses
HOST=0.0.0.0 ./scripts-tools/run.sh   # picks up certs/ automatically
```

Then trust the CA on the phone, once:

```bash
python3 -m http.server 8000 --directory certs
# on the phone, open http://<your-ip>:8000/ca.crt
```

- **iOS** — Settings → *Profile Downloaded* → Install. Then
  Settings → General → About → **Certificate Trust Settings** and switch on
  "Read Aloud local CA". Both steps are required; the second is easy to miss
  and without it Safari still refuses.
- **Android** — Settings → Security → Encryption & credentials →
  Install a certificate → **CA certificate**.

`certs/` is gitignored: it holds private keys.

**In Docker**, mount the directory and run as the user that owns the key —
it stays mode 600 on the host, so the container's own unprivileged uid cannot
read it:

```bash
docker run -d -p 8765:8765 --user "$(id -u):$(id -g)" \
  -v "$PWD/certs:/certs:ro" \
  -e T2S_SSL_CERT=/certs/server.crt -e T2S_SSL_KEY=/certs/server.key \
  read-aloud
```

Without `--user` the server exits with a permission error, and says so.

### 2. Tailscale (easiest if you already use it)

```bash
tailscale cert "$(tailscale status --json | jq -r .Self.DNSName | sed 's/\.$//')"
HOST=0.0.0.0 T2S_SSL_CERT=<name>.crt T2S_SSL_KEY=<name>.key ./scripts-tools/run.sh
```

A real, publicly-trusted certificate for your tailnet name. Nothing to install
on the phone, and it works away from home.

### 3. cloudflared (temporary public URL)

```bash
./scripts-tools/run.sh &                          # plain http is fine here
cloudflared tunnel --url http://localhost:8765
```

Gives a `https://<random>.trycloudflare.com` address. Convenient for a quick
test on someone else's phone; note that the text you read passes through
Cloudflare, which the other two options avoid.

## Installing

Once you are on https:

- **Android / Chrome** — an **Install** button appears in the top bar, or use
  the browser menu → *Install app*.
- **iOS / Safari** — Share → **Add to Home Screen**. iOS has no install prompt
  API, so the app shows the instruction instead of a button.
- **Desktop** — Chrome and Edge show an install icon in the address bar.

Installed, it launches without browser chrome, keeps its own icon, and the
interface loads instantly from cache.

## What works on a phone

| | |
|---|---|
| **Lock-screen controls** | Play, pause, next and previous sentence appear on the lock screen and in the notification shade, and headset buttons work. The sentence being read is shown as the title. |
| **Screen stays awake** | Reading holds a wake lock so the phone does not dim and hide the highlight. Toggle in *Reading aids*; ignored where the API is missing (iOS before 16.4). |
| **Background playback** | Audio continues when you switch apps or lock the screen. Highlighting resumes when you come back. |
| **Share into the app** | Share text from any app to Read Aloud and it starts reading. Android; iOS does not implement share targets for web apps. |
| **Open .md files** | On desktop Chrome/Edge, `.md` files can be opened with the installed app. |
| **Offline** | The interface loads offline. **Speech does not** — audio is generated by the server, so with no connection the app opens and says it cannot reach it. |

## What the interface does differently on a phone

- Settings open as a **bottom sheet** rather than a side drawer — reachable
  with a thumb.
- The transport bar has its own **speed row** with − / + buttons either side of
  the slider, because a slider alone is fiddly while walking.
- The progress bar is **14 px tall** and scrubbable; on desktop it is 6 px.
- Top-bar buttons become icons; every target is at least 44 px.
- Layout runs under the notch and home indicator, with `env(safe-area-inset-*)`
  keeping the controls clear of both.
- Hover styles are behind `@media (hover: hover)`, so a tap does not leave a
  stuck highlight.
- Select and textarea font size is pinned to 16 px, below which iOS Safari
  zooms the page when a field is focused.
- Landscape on a short screen drops the second transport row.

## Known limits

- **iOS mutes web audio when the ringer switch is off.** This is a platform
  rule for `<audio>` elements and there is no way around it from a web app.
  If the reader looks like it is playing but you hear nothing, check the
  side switch.
- **iOS wake lock** needs 16.4 or newer. The setting hides itself otherwise.
- **Speech needs the server.** A phone away from your network cannot read
  unless you expose the server to the internet (Tailscale, or a tunnel).
- **First sentence after a cold start** takes a few seconds while the model
  loads. After that it is ~150 ms per sentence on GPU.
